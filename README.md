## How I work — five principles

1. **Depth over breadth.** Get genuinely good at the small set of tools that run modern DE — Spark, Kafka, Airflow, dbt, SQL, AWS — deep enough to debug them at 2am.
2. **Build in the open.** Half-finished things shipped publicly beat polished things that only exist in your head.
3. **Log what you don't know.** Claimed skills are debt. Honest gaps are credibility.
4. **The pipeline is the product.** If it breaks, the business breaks. Treat it that way.
5. **Write about the work.** The engineers I respect most can also explain things in plain English.
